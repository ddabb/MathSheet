### 1.1 为什么是口算题卡
- 刚需高频：口算是小学低年级数学的日常作业形态，"每天一页 20-50 道"是一二年级家长的长期任务；题卡打印是标准作答介质。

- HarmonyOS NEXT 生态空缺：应用市场检索"口算/题卡"，缺乏高质量原生买断应用；存量竞争形态为小程序（广告 + 不可控外链）与订阅制 App（年费 ¥100+）。

### 6.2 构造式生成（关键技术点①：约束满足先于随机）
- 核心思想：不"随机出题再校验"（低效且易死循环），而是**按运算反向构造**使硬约束先天满足：
  - 加法：在和区间 [lo,hi] 内随机和 s → 随机加数 a ∈ [max(0, s−上限), min(上限, s)] → b = s − a（操作数与和同时受控）；"不进位"约束 = 个位相加 <10 条件下重采样；
  - 减法：随机被减数 x ∈ [lo,hi] → 减数 y ∈ [0, x]（结果非负先天保证）；"不退位"同理；
  - 表内乘法：两因子 ∈ [2,9]；两位×一位：按位构造被乘数；
  - 除法：**先随机商 q 与除数 d → 被除数 = q × d**（整除与商/除数范围先天保证，核心技巧）；
  - 混合两步：按运算树自顶向下构造（先定最终结果与第二步运算，回推第一步操作数），中间结果满足整除/非负；
  - 填空：从完整式随机挖去一个操作数或结果位。
- 拒绝采样兜底：仅用于进退位等弱约束（≤64 次/题），硬约束一律构造保证——理论上无死循环；
- 难度参数 ProblemSpec 为显式数据类（范围/进退位/括号/表内域），年级预设 = 题型 × 难度的纯数据组合表（可测可扩展）。

### 6.3 版面与渲染管线（关键技术点②：位图所见即所得）
- 版面引擎纯函数：输入（题目列表 + LayoutSpec{列数/边距/字号/题头开关/页尺寸 2480×3508px = A4@300dpi}）→ 输出每题 (页号, x, y) 坐标布局树——黄金用例直测（坐标快照断言）；
- 渲染：drawing.Font（@ohos.graphics.drawing）逐题光栅到位图，每页一张白底 PNG（Flate 压缩典型 < 200KB/页）；**M0 首日查证** drawing.Font 文本光栅与度量 API，兜底 OffscreenCanvas fillText（ArkUI 标准路径，1.4.x 已验证）；
- PDF：移植自有 PdfComposer（已验证：位图页合成 + 页边距 + FIT 模式）→ 矢量容器 + 位图页 = 打印所见即所得，字体渲染由系统保证；
- 内存控制：逐页"渲染 → PNG 编码 → 释放"，峰值单页缓冲 ≈ 35MB（2480×3508 RGBA），10 页导出预算 < 3s（进度条遮罩）；
- PNG 长图：多页纵向拼接导出（ImagePacker）。

### 6.4 持久化设计（关键技术点③：物化存储防版本漂移）
- 卷库存**物化题目**（题面 + 答案 + 批改状态 JSON），而非 (spec, seed) 重生成引用——应用版本演进后生成算法微调不会导致历史卷"重开变题/批改错位"；
- 错题本同样物化存储（题面 + 答案 + 来源卷引用 + 标记时间）；重练卷 = 错题原题 + 按 {spec, 新种子} 生成的同类新题按 1:2 混编；
- 体积预算：单卷 ≤ 16KB（200 题 × ~80B 实测），500 卷 + 错题本 < 9MB——沙箱直存 JSON，无需数据库；
- 打卡天数/每日一练配置：preferences 轻量存储。

## 8. 测试与质量方案（复用 PocketToolbox 方法论）
- **mathCoreTest TDD 先行，性质测试为核心**：单题断言无意义，批量性质断言才是引擎正确性证明——每题型 × 难度 1000 次批量断言（结果范围/非负/整除/进退位约束全量成立）；去重（常规 + 可行域不足放行）；种子复现（同 seed 两跑逐题相等）；Layout 黄金用例（坐标快照）；Rng 分布抽查（和值直方图粗校验防偏斜）；
